## What landed

- `CACHE_TTL_MS`: 5 min → **60 min** (session-1 law), keyed by town slug.
- **SWR**: `cacheGet` now returns `{tempF, state:'fresh'|'stale'}`. A hit —
  fresh OR stale — serves the last-known temp instantly; a stale hit also
  schedules a quiet background revalidation that updates the cache for the
  next request. A seen town never blocks on upstream.
- **Neighbor-ring prefetch**: `neighborRing()` expands each bbox side by
  span×1, drops towns already served, skips towns whose cache entry is
  fresh. Prefetch runs fire-and-forget, ≤50 towns (`MAX_PREFETCH_TOWNS`),
  ≤10 concurrent upstream (`MAX_UPSTREAM_CONCURRENCY`), deduped against
  in-flight slugs via a module-level `inFlight` set.
- Determinism (R17): no `Math.random`/`new Date`; `Date.now` appears only as
  the injectable clock default. All tests inject `now` — zero `Date.now` in
  test code. Ordering stays data-order (pop desc), never RNG.
- Seams: `opts.schedule` (capture background promises in tests),
  `opts.prefetch=false` (isolate the served path), `resetWeatherCache()`.

## Catches / findings

1. **Test schedule seam**: fire-and-forget `schedule` defaults make
   background work invisible to assertions. Injecting `(p) => bg.push(p)`
   and awaiting keeps tests deterministic (no timers, no sleeps).
2. **Synchronous-schedule accounting**: the injected scheduler starts the
   SWR refresh immediately, so "zero blocking calls" is asserted on the
   response, and refresh call-counts are checked after awaiting the
   captured promise.
3. **neighborRing fixture sensitivity**: with `PREFETCH_RING_FACTOR=1` the
   ring band is exactly one span wide — a fixture town must sit inside the
   expanded box, not just outside the original one (first fixture at
   lon 0.5 for a 0.2-span box fell beyond the ring; moved to (0.15, 0.15)).
4. **Prefetch + legacy call-count tests**: the old "second request within
   TTL makes ZERO calls" assertion counted ring prefetches too; those tests
   now pass `prefetch:false` to isolate the served path. Production always
   prefetches.
5. **60-min TTL is a demo-app choice** (owner: "fresher not needed"); the
   60-min `Cache-Control: public, max-age=60` HTTP header (60 s) is
   unchanged and stricter than the server cache.
